# 背包：把做好的积木攒下来，下次直接取

> 适用场景：你（AI）刚啃下一件有难度的事 —— pen 文字引擎、弹幕骨架、ECS 骨架、
> 存档读写、UI 按钮骨架 —— 与其下次从零再搭一遍，不如存进背包；
> 或者用户说「上次那个画字的积木呢 / 直接搬过来用」。

## 一句话

**skill 区存「怎么做」，背包存「做好的东西」。** 积木 + 它要的变量/列表（含值）一起存，
下次 `scratch_backpack_load` 一条命令注进项目。

## 存之前先问一句

这是硬规矩：**不要自动攒**。自动收集会攒一堆一次性的垃圾，用户看两次就不看了，背包就废了。
问法就一句：「这个要不要存进背包？下次直接能用。」用户说存再存。

值得存的：结构复杂、调试花过时间、以后大概率还要用。
不值得存的：三五行、一次性、跟这个作品绑死的（比如"这个角色开头移动 10 步"）。

## 怎么存

```
scratch_list_scripts({ target: "Sprite1" })        // 先看清有哪些脚本、哪些是真脚本
scratch_backpack({
  action: "save", name: "pen-text", target: "Sprite1",
  scriptIds: [<脚本根 blockId>, ...],              // 或 all: true 存整个角色的脚本
  title: "pen 文字引擎（画字/找字/画文本）",
  description: "要在舞台上画字的时候用",
  tags: ["pen", "text"],
  notes: "把「字模」列表换成要画的字；画之前先 pen_clear"
})
```

- `name` 是文件名，中英文都行（会清洗非法字符）。同名再存要显式 `overwrite: true`。
- **`notes` 是写给下次的自己看的**：参数在哪改、有什么前提、踩过什么坑。别省。
- 存的东西里会自动带上引用的变量/列表**和它们的值**（字模表就是命）。
  **列表默认只带前 1000 项**：返回里 `truncatedLists` 非空就是被截了，别指望它搬运大数据；
  真要连整张表一起存（字形库那种几十万字符），传 `listLimit: 50000`（或更大），
  截断时返回里可数（不是静默的）。
- **变量的作用域会一起存**：舞台上建的（全局）恢复时还建在舞台，角色局部变量建在目标角色。
  存的时候给 `variables: [{ name, type, scope: "global" }]` 可以强制。
- 存完返回 `requires`，那就是"这条片段依赖什么"的清单。

> 本机背包里已经有 **`文字引擎`**（画笔中文文字，4 个自定义块 + 两张字形表，约 5.5 MB）。
> 要画字直接用 `scratch_backpack_load({ name: "文字引擎" })`，别自己写 —— 用法见 **pen-text.md**。

## 怎么取

```
scratch_backpack({ action: "list" })               // 扫目录：名字/标题/块数/标签，很便宜
scratch_backpack({ action: "read", name: "pen-text" })   // 要看块体、想改参数时
scratch_backpack_load({ name: "pen-text", target: "Sprite1", x: -200, y: 40 })
```

- 注入时**变量引用会被落地**：目标里有的按名字接上，没有的就地补建（内容用背包存的那份）。
  所以搬到别的角色、别的作品都能用 —— 不会再出现一堆「变量未找到」的块。
- `variableValues` 可以直接换内容（换字模表最常用）：
  `scratch_backpack_load({ name: "pen-text", variableValues: { "字模": ["甲", "乙"] } })`。
- 坐标是**整体平移**：不给 `x/y` 就落到 `48,48`，片段内部的相对排布保留。
- 它是写操作，受插件设置里的 `safety` 档位管：`preview` 档会先返回 `planId`，
  用户点头后 `scratch_apply({ planId })` 才真注进去。

## 三条踩过的坑

1. **调了自定义积木却没存它的定义。** 存的时候如果警告「调用了自定义积木「X」但片段里没有
   它的定义」，说明你得把 `procedures_definition` 那条一起存 —— 否则注进去是空转，GUI 也不报错。
2. **别用背包搬大数据。** 它存的是"积木 + 小配置"，不是资源仓库。大列表、造型、音频都不在里面。
3. **删错了不会真没。** `delete` 只是挪进 `_trash/`，告诉用户一声，需要恢复就把文件移回来。
