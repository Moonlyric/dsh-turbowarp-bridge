# 画笔 3D：一条能跑起来的管线

> 适用场景：要做伪 3D（第一人称走廊、赛车、俯瞰 3D、立体迷宫），又不想用扩展。
> 下面的每一段都是从真作品里读出来的**能跑的结构**，不是数学课。
> 关键认知：**难的不是投影（一行乘法），是裁剪**。把裁剪写对，3D 就成立了。

---

## 1. 相机长什么样：一张 9 项的列表

```
摄像头方向向量座标 = [ 右x, 右y, 右z ,  上x, 上y, 上z ,  前x, 前y, 前z ]
摄像头x, 摄像头y, 摄像头z        ← 三个标量
像距 = 200                        ← 焦距，越大越"长焦"
```

三个基向量**不需要单位长度**（下面除法会把长度除掉），所以可以直接存"带缩放"的方向，改 FOV 时只改这个列表。相机旋转 = 重算这 9 个数（一次三角），不是每帧对每个顶点做旋转矩阵 —— 这是整条管线最快的地方。

## 2. 世界 → 相机：三次内积

```
检测xyz(x, y, z):
  向量 = (x − 摄像头x, y − 摄像头y, z − 摄像头z)
  相对X = 内积(向量, 右) ÷ 模(右)
  相对Y = 内积(向量, 上) ÷ 模(上)
  相对Z = 内积(向量, 前) ÷ 模(前)     ← 这就是深度
```

内积 `= x1x2 + y1y2 + z1z2`，模 `= √(x²+y²+z²)`。两次都是普通积木，不用扩展。

**为什么除以模**：存"带缩放的基向量"时内积结果也被缩放了，除回去才得到真正的投影长度。好处是基向量可以随手写、不用归一化。

## 3. 透视投影：一行

```
投影xy(相机x, 相机y, 相机z):
  屏幕x = 相机x × (像距 ÷ 相机z)
  屏幕y = 相机y × (像距 ÷ 相机z)
```

就这一行。近大远小、消失点全在里面。`相机z` 必须 > 0（在镜头前方），所以下面必须先裁剪。

## 4. 近平面裁剪：**这一段写不对，整个 3D 就会闪**

一条线段的两个端点，可能一个在镜头后、一个在前。直接把"后面那个"投影会得到**镜像的鬼影**（除以负数），所以先把它切到近平面上：

```
线段裁剪(点1, 点2):
  如果 z1×z2 > 0:                    ← 两端在同一侧，不穿过平面
     交点 = NaN（标记"没有交点"）
  否则:
     t = |z1| ÷ (|z1| + |z2|)        ← 参数插值，不是解方程
     交点 = 点1 + (点2 − 点1) × t      ← x y 各算一次
```

然后：

```
画线段(点1, 点2):
  检测xyz(点1); 检测xyz(点2)                       ← 转到相机空间
  如果 (z1 < 5 且 z2 < 5): 停止这个脚本             ← 整段在身后，直接丢掉
  线段裁剪(点1, 点2)
  如果 交点是 NaN: 两端都正常投影
  否则: 把"在近平面前面那一端"换成交点，再投影        ← 只换后面那个
  绘制线段(屏幕点1, 屏幕点2)
```

**坑**：
- `z1×z2 > 0` 判"同侧"是**乘号而不是比较号** —— 写 `z1 > 0 且 z2 > 0` 会漏掉"都在前面"的情况（那也该走正常投影）。
- 阈值用 `5` 而不是 `0`：太靠近 0 时 `像距/z` 会炸成几百倍的坐标，画出来是一根乱飞的线。
- `停止这个脚本`（`control_stop` 的 "this script"）是**早退**，别用 `如果...否则` 套五层。

## 5. 屏幕裁剪：真作品是"数到两个交点就收工"

投影完的坐标可能落在舞台外（`|x| > 240` 或 `|y| > 180`）。画笔会照画（只是看不见），但**一条线一端在屏幕内、一端在屏幕外几万像素**时，画笔的线段会拖慢渲染。

三个分支分头处理（`两点都在内` / `一内一外` / `两点都在外`）。最值得抄的是**两点都在外**那一支 —— 它不试像素，只数交点：

```
◇ 绘制直线,两点都在舞台外(x1,y1,x2,y2)
  count = 0
  如果 (左边界交点y 在 −180…180 之间) { 移到(−240, 左边界交点y); 落笔; count += 1 }
  如果 (右边界交点y 在 −180…180 之间) {
     移到(240, 右边界交点y)
     如果 (count = 0) { 落笔 } 否则 { 抬笔; 停止这个脚本 }     ← 两个交点都拿到了，画完了
     count += 1
  }
  如果 (上边界交点x 在 −240…240 之间) { …同上… }
  如果 (下边界交点x 在 −240…240 之间) { …同上… }
```

**关键洞察**：一条线段最多和舞台矩形相交两次。所以只要按四条边check一遍，**收集到第 2 个交点就可以 `停止这个脚本`** —— 不用管它是不是真的在屏幕内，也不用逐像素试。四个交点坐标（与左/右/上/下边的交点）在调用前就算好，塞进 `29*左边界交点y` 这类变量里。

**坑**：
- 交点必须**同时检查它落在对应的那条边上**（左边界交点要看 y 在不在 −180…180）。不检查的话，延长线在画面外的交点也会被当成真交点，画出一条穿过整个屏幕的错误直线。
- `count` 用来自适应"第一个交点落笔、第二个交点抬笔"，因为两个交点的出现顺序不固定（线可能从左边界进、从下边界出）。


## 6. 每帧的节拍（谁先算）

```
刷新（广播）:
  ① 清屏（笔迹全部擦除）
  ② 各子系统按 z 从远到近把要画的东西排好（或直接塞进有序的绘制队列）
  ③ 一趟画完：线段 / 多边形 / 贴片
  ④ 画 HUD
```

顺序反了就会"近的被远的盖住"。**深度排序**要么每帧对可见物排序，要么像另一份作品那样维护一张按图层有序的插入表（见 `render-queue.md`）。

## 7. 返回值约定：`out<过程号>*<字段>`

Scratch 自定义块没有返回值。这份作品的约定是：

```
◇ 8求向量间内积 … [warp]
  out8*内积 = x1×x2 + y1×y2 + z1×z2      ← 过程号 8

◇ 19检测…的投影xy
  out19*投影x = …
  out19*投影y = …                        ← 同一个过程可以"返回"多个值
```

**抄法**：过程名前面带编号、返回变量以 `out<编号>*` 开头。好处是不用在调用完以后猜"刚才那个中间变量叫什么"，也不会跟别处的 `x` `y` 打架。代价是要背名字 —— 但比"变量未找到"好得多。

## 8. 性能

- 一条边 = 2 次相机变换（各 3 次内积 + 3 次模）+ 1 次裁剪 + 1 次画线。**每条边都要重算内积**，所以物体顶点数直接决定帧预算。一个走廊场景几十条线没问题，几百条就要考虑"只画视野内的"。
- 画笔的 `笔的大小` 可以按距离给（`1/z` 量级），近粗远细，观感立刻好一截。
- 相机基向量**只在相机转向时重算**，别每帧对每个顶点算三角函数。

## 9. 什么时候别这么干

- 要**实心面 + 光照**：这套是线框/色块，填面会掉进"多边形填充"那个坑（要用克隆体三角形或 `pen` 的三角形填充扩展）。
- 只是想要"伪 3D 视角的 2D"（比如俯视 45°）：只要 y 轴压扁 + 按 y 排序，别上投影。
