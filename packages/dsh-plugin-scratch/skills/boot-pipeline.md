# 启动管线：分批初始化 + 造型预热（把卡顿挪到载入阶段）

> 适用场景：造型几百张、开场/切场景会卡一下；或者你要做一个"载入中"进度条；
> 或者游戏里第一次冒出某个单位时掉帧。
>
> 来源：一个 50 角色、1430 张造型的还原类作品。它开场做的事是：
> **每帧初始化一个角色（29 步），再把 1382 张造型 × 档位 = 1745 次"预渲染"摊到几百帧里跑完为止。**

---

## 1. 三段式启动（广播名固定，谁都能接）

```
Metro（总调度角色，也是唯一发广播的角色）:

绿旗
 等到 modelReady > 0                    ← 模型/存档先就绪
 隐藏
 广播并等待「init-BootLoader」
 等待 0 秒
 广播并等待「init-StartupGate」
 等待 0 秒
 初始化场景（bootSceneBegin）
 计时器归零；lastTimer = 0
 重复执行直到 startupGateBlocked = 0 {    ← 闸门关着时"空转一帧"
    frameDt = 计时器 − lastTimer
    frameDt = min(frameDt, 0.075)         ← 掉帧时不让物理穿模
    lastTimer = 计时器
    画一帧
    等待 0 秒
 }
 进 forever 主循环
```

要点：

- **一个角色一个广播**：`init-Station`、`init-Glow`、`init-Passenger`…… 每个角色只接自己那一个。
- **`广播并等待` 后面一定跟 `等待 0 秒`**。`广播并等待` 会把所有接收方**挤在同一帧**里跑完；中间不隔一帧，40 个角色的初始化等于一帧干完。
- 每初始化完一个角色 `bootInitialCompleted += 1`，配合 `bootInitialTotal = 29` 驱动进度条 —— **进度条的数据源就是这个计数器，不是估算**。
- **闸门变量**（`startupGateBlocked`）比"等一个长 `等待`"可靠：载入代码随时可以把闸门关上，主循环自动停住，不用去改任何 `等待` 的秒数。

## 2. 造型预热：真正的开销在"第一次显示"

矢量造型在**每次缩放档位变化**时都要重新栅格化。第一次显示的代价落在玩家已经玩起来的时候 = 可感知的掉帧。
这个作品的做法：载入阶段主动把每张造型在几个尺寸下各画一次，画完立刻清掉。

```
当接收到「boot-warm」
 如果 actorId = 0                        ← 只让"本体/一个空闲克隆"干，别让 300 个克隆一起干
   bootWarmCostume = 1
   重复执行直到 bootWarmCostume > bootWarmCounts[我的槽]
     调用 bootWarmCostume()              ← 见下
     等待 0 秒                            ← 每张造型让出一帧
     bootWarmCostume += 1
   隐藏
   bootWarmRolesDone += 1                 ← 告诉调度者"我这个角色完事了"
```

```
◇ bootWarmCostume()          ← 每个角色各有一份（76 行，40 份）
  bootWarmPass = 1
  重复执行直到 bootWarmPass > bootWarmPasses[我的槽]      ← 本角色预热几档
    bootWarmSize = 100
    如果 bootWarmPasses[我的槽] > 1
      如果 bootWarmPass = 1 → bootWarmSize = 25
      否则如果 bootWarmPass = 2 → bootWarmSize = 50
      否则如果 bootWarmPass = 4 → bootWarmSize = 120
    设 虚像 效果为 100                     ← 画了也看不见
    换成 造型 (bootWarmCostume)             ← 造型序号（变量，不是造型名）
    设 大小为 bootWarmSize
    移到 x:0 y:0
    显示
    图章                                   ← 逼渲染器真的走一遍
    清空                                   ← 立刻擦掉，别留在画笔层
    bootWarmCompleted += 1
    bootWarmPass += 1
```

三个细节值得抄：

1. **`虚像 100` + `图章` + `清空`**：既要真的走渲染管线，又不能留在画面上，也不能留在画笔层里。
2. **`显示` 必须有**：隐藏的角色走不到渲染。
3. **档位是配置，不是写死**：1→25%、2→50%、3→100%、4→120%，这个作品的实际配置只用了 1 档和 2 档（`bootWarmPasses = [2,2,…,1,1,1,…,2]`），**4 档的分支是留给以后加角色的**。

## 3. 配置表：一个角色一项，而不是硬编码

| 全局表 | 长度 | 含义 |
|---|---|---|
| `bootWarmCounts` | 40 | 每个角色有多少张造型要预热（最大 **343**） |
| `bootWarmPasses` | 40 | 每个角色预热几档尺寸（1 或 2） |
| `bootWarmTotal` | 1 | **Σ(造型数 × 档数) = 1745** |
| `bootWarmRoleTotal` / `bootWarmRolesDone` | 1 / 1 | 40 / 40，调度者靠这两个数判断结束 |
| `bootWarmCompleted` | 1 | 已完成的预热次数，驱动进度条 |

**共表 + 每角色读自己那一项**，加一个角色 = 在表尾加一项 + 加一个 `init-<名字>` 接收脚本，调度逻辑一行都不用改。
这一点比"预热"本身更值钱：**配置集中在表里，行为分散在各角色里** —— 两边都不需要知道对方的存在。

## 4. 这套东西什么时候值得

- 造型多（几百张）、是矢量（SVG）→ 值得，收益就是"第一次出现不掉帧"。
- 造型已经是位图 → 收益小得多，别做。
- 只有几十张造型 → 别做，只会让开场变慢。
- 有载入条/开场动画 → 顺便做，用户本来就在等。

## 5. 最小可抄版本（三四十块积木）

```
角色「加载」:
  绿旗 → 广播并等待「init-A」→ 等待 0 秒
       → 广播并等待「init-B」→ 等待 0 秒
       → 广播「warm」                      ← 不等待，各角色自己摊帧
       → 重复执行直到 已预热角色数 ≥ 角色总数 { 画进度条；等待 0 秒 }
       → 广播「开始」
角色 A/B/…（每个角色各一份）:
  当接收到「init-自己」→ 建好自己那摊东西
  当接收到「warm」    → 重复 (造型数) 次 { 虚像100 → 换造型 → 图章 → 清空 → 等待 0 秒 }
                        隐藏 → 已预热角色数 += 1
```

## 6. 怎么验证真的生效了

- 载入阶段 `bootWarmCompleted` 在涨、`bootWarmRolesDone` 最终等于 `bootWarmRoleTotal` —— 用 `scratch_variable({ action:"get" })` 或 `scratch_watch` 看，别靠肉眼。
- 用 `scratch_profile({ seconds })` 看 p95/max：预热做过之后，**进游戏后的第一波显示不应该再出现尖峰**；如果尖峰还在，说明档位配少了（该角色实际显示尺寸没被覆盖）。
- 预热没生效最常见的两个原因：忘了 `显示`；或者 `重复` 里没有 `等待 0 秒` —— 那样预热本身会变成一次性卡死几秒，反而更糟。
