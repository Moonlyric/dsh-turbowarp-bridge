# 项目策划：从「做个什么」到「能做完」

> 适用场景：用户说「帮我做个游戏/动画」但没细讲时读。
> 社区作品的完成度经验——学生的作品烂尾不是因为代码差，是因为没想清楚就开写。

## 先问自己（也问用户）的 5 个问题

1. **30 秒版本是什么样**：用户玩/看 30 秒后的核心体验一句话能不能说清？说不清就先做减法。
2. **复用还是自造**：关卡制的 3 个关卡 > 想做 10 个关卡烂尾在第 4 个。样本里的高完成度作品全是「小而深」：一个机制（弹幕/节点图/像素画）做到底。
3. **素材从哪来**：Scratch 社区靠造型库+自画。AI 能给的是：SVG 造型（scratch_add_costume）+ pen 绘制 + 图形拼接。需要照片级素材的方案在 Scratch 里不现实。
4. **第一次交互发生在几秒内**：标题画面别超 5 秒。耐看的作品都「快速进核心」：封面→一键开始。
5. **做完的标志是什么**：定义「最小可玩」，到了就收工。加功能列表写进存档变量，不写进当前版本。

## 体裁经验（样本覆盖到的体裁谱）

> 「块数量级」只是**给你估工作量**用的粗档位，不是评分标准；同一个体裁做得深浅差别很大。

| 体裁 | 块数量级 | 核心机制 | 最大风险 |
|---|---|---|---|
| 算法/数学演示 | 15-100 | 一个公式/视觉化 | 讲不清理科梗 |
| 工具（编辑器/渲染器） | 700-1900 | 数据结构+pen | 学习成本高，要 UI 情商 |
| 弹幕/动作游戏 | 1000-5000 | 克隆池/列表弹幕+碰撞 | 性能（TW 无克隆上限但要控量；发回原版 sc 则按 300 限保守设计） |
| RPG/大世界 | 5000+ | 状态机+广播总线+相机 | 烂尾（变量爆炸） |

**AI 的甜点区：前两档**。RPG 级别建议先搭骨架（状态机+1 个场景跑通）再谈填充。

## 结构模板（开新项目的默认起手）

```
Stage: 全局变量（游戏状态、分数、关卡）+ 时钟脚本
System: _ Init 广播 → 初始化一切 → 广播 Start Game
Player: 键盘控制 + 主循环（forever+wait 0.02）
Enemy(可选): 生成器（克隆/列表）
UI: 分数显示（造型数字或说）+ 转场精灵
```

起手 5-8 个角色封顶。全部默认名改成职责名——这是 agent 少数**必须强迫症**的地方。

## 素材速成（AI 的优势区）

- **SVG 造型**：scratch_add_costume 直接注入。纪律：viewBox 对齐 48x50 旋转中心；纯色块+描边风格最稳（Scratch 舞台小，细节会糊）
- **几何拼接**：简单角色用几个矩形/圆拼（社区像素风本质也是拼接）
- **画笔 HUD**：血条/进度条 pen 画，不占造型位

## 節奏设计三招（那些耐玩作品的隐形功底）

1. **首次反馈 < 0.1s**：按钮按下立即换造型+音效，逻辑可以慢半拍
2. **失败要能立刻重试**：Game Over 界面一键重来（常见做法：`死亡界面` 专用精灵）
3. **背景音乐低音量默认开**：`将音量设为 30%`——静音键给用户，不是你不放

## 别学学生的地方（策划版）

- ❌ 开局 3 分钟过场动画——没人看（耐看作品的过场要么 < 10 秒，要么可跳过）
- ❌ 主菜单 7 个按钮 6 个没做——按钮列表先砍到 3 个（开始/设置/关于）
- ❌ 「借鉴」知名游戏全部机制——选一个机制做深
- ❌ 教程关 20 步——教 3 步就放真关卡，边玩边教
