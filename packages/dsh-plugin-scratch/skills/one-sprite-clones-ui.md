# 一个角色 + 克隆体，把整套界面做出来

> 适用场景：界面/控件很多但结构相似（按钮、滑块、格子、工具栏、时间轴），或者要做**编辑器**
> （画布 + 工具栏 + 属性栏）。也适用于你发现"每加一个按钮就多一个角色"已经忍不了的时候。
>
> 这份是从一个**2 个角色的动画编辑器**（4600+ 块）里读出来的组织方式：
> `main` 一个角色 84 段脚本，其中 458 块是「当作为克隆体启动时」。
> 它和 `proven-patterns.md` 第 10 条（一个关注点一个角色）不是对立，是**另一种分工**：
> 那边按"职责"拆角色，这边按"控件长得像不像"合并成克隆体。

---

## 1. 骨架

| 谁 | 干什么 |
|---|---|
| 一个角色（比如 `main`） | 承载**所有**界面元素和控件逻辑 |
| 一条 `clone(造型, 大小, x, y, …) [warp]` | 批量造克隆体 |
| 一条「克隆体启动」 | **每个克隆体的主循环**，按"我是谁"分派 |
| 每个克隆体的私有变量 `_clone` | 它在同一批里的序号，用来取自己的参数 |

```
◇ clone(造型, 大小, x, y, …) [warp]
  换成 造型
  大小设为 大小
  移到 x y
  重复 time_a 次 {
    如果 (这批要编号) { _clone = _clone + 1 }
    克隆自己
    x = x + x2 ; y = y + y2          ← 沿着一条直线摆一串
  }
```

一条 `clone(...)` 调用能摆出**一整排按钮/格子**（起点 + 每格步长 + 个数），比在编辑器里拖 40 个造型省事得多。

## 2. 克隆体怎么知道"我是谁"

**用造型编号当类型标签。**

```
◆ 当作为克隆体启动时
  显示
  forevor {
    如果 (造型编号 = time)            → 我是"时间轴"
    如果 (造型编号 包含 "function bar_"） → 我是工具栏的某一格
    如果 (造型编号 = "slide bar_a")      → 我是滑块
    …
  }
```

要点：

- **`包含` 当分组**：`造型编号 包含 "function bar_"` 一次命中这一族的全部造型，加新按钮只需要起个同前缀的造型名 —— 不用改分派代码。
- **造型名就是类型名**。别起 `造型1` `造型2`，起 `function bar_a` `slide bar_b`。造型名是这套架构里唯一的"类型系统"。
- 精确的用 `=`，成组的用 `包含`。一个 458 块的 `forever` 里就是几十个 `如果`，**顺序 = 优先级**（写在前面先命中）。

## 3. 克隆体怎么取自己的参数

全局放一张参数表（平行列表），克隆体用 `_clone` 当下标：

```
造的时候：设 up_a[_clone] = 3    ← 或者把参数整体 add 进一张表
用的时候：item _clone of up_a
```

因为克隆体没有"构造参数"，**参数只能靠序号从表里取**，或者靠造型名。选一种，别混用。

## 4. 命中测试：用坐标区间，别用「碰到鼠标指针」

```
如果 (鼠标x > 左边界 且 鼠标x < 右边界 且 鼠标y > 下边界 且 鼠标y < 上边界) {
  …被点了…
}
```

**为什么**：

- `碰到鼠标指针` 依赖造型的实际像素形状，按钮做一半透明、或者造型是圆角时判定会很怪；而且它要过一次渲染器碰撞检测，比四个比较慢。
- 坐标区间是纯算术，还能**顺手做九宫格**（`round((鼠标x − 左) / 格宽)` 直接得到"第几格"）。
- 按钮摆成等距网格时，命中测试是**一行除法**，不用循环。

## 5. 交互的三个小件

```
悬停：如果 (命中) { 亮度设为 5 } 否则 { 亮度设为 0 }      ← 一行，够用
点击：如果 (命中 且 鼠标按下) { 调用 动作; 等到 <鼠标没按下> }   ← 等到松开 = 防连点
拖动：如果 (按下 且 命中) { 重复直到 <松开> { 移到 鼠标x 鼠标y } }
```

`等到 鼠标没按下` 是这套里最省事的防连点手段：不加的话，一次点击会被 30 个 frame 各处理一次。

## 6. 撤销栈：15 块积木的通用写法

编辑器的灵魂。真作品的做法简单到意外：**一张扁平表，两条记录一项**。

```
全局：history（列表） 、 history_n（计数器）

◇ add history(类型, 内容)          ← 类型是单个字母
  如果 (len(history) > 上限) { 删掉最早的 }
  history 加入 类型
  history 加入 内容
  history_n = history_n + 1

◇ restore history(步数)            ← +1 重做、−1 撤销
  history_n = history_n + 步数
  restore history_i( item (history_n×2 − 1) of history , item (history_n×2) of history )

◇ restore history_i(类型, 内容)
  如果 (类型 = "a") { 换成画面 内容 }                    ← 每次记录的粒度按类型分
  如果 (类型 = "c") { 拆开 "x,y,size" → 分别设回去 }
  如果 (类型 = "p") { 拆开 "pen,size,alpha" → 分别设回去 }
  如果 (类型 = "s") { 速度 = 内容 }
```

三条设计决定，直接照抄就行：

1. **类型用字母，内容用字符串**。一条记录 = 2 项，撤销栈不需要每类一个列表。
2. **粒度按"一次用户操作"**，不是按"一次变量变化"。每类操作自己决定要存什么（画一笔存整张画面？存笔刷参数？）。
3. **恢复时用分派**，不是"把所有状态整份存下来"——整份快照在 Scratch 里太贵（一份就是几千项）。

**坑**：撤销完还要"重做"的话，计数器只能走到表尾就停；做了新操作要把"未来"截掉（`repeat (len − n×2) { 删最后一项 }`）。真作品里这段截断写成了 `len > history×2`，因为 `history` 同时是计数器和列表名，实际永远不成立 —— **这就是没测过的死代码**，抄的时候别抄错。

## 7. 什么时候别这么干

- 控件数量 < 5、互相不像 → 老老实实一个角色一个控件，比在 458 块里加一个 `如果` 划算。
- 控件**长得完全不同**（一个画布 + 一个时间轴 + 一堆对话框）→ 按"变化频率"拆：画布一个角色（每帧重画），工具栏一个角色（几乎不变）。全都塞一个角色，那个 `forever` 会变成全项目最难改的一块。
- 需要**多实例**（同一个按钮出现两次）→ 正好，克隆体天生支持；但 `_clone` 序号必须在同一批里唯一，别用全局计数器跨批续号。

## 8. 这套的代价（抄之前先认）

- 「克隆体启动」会变成一个几百块的 `forever`，**任何控件出问题都要在这一个脚本里找**。缓解办法：造型名分组（第 2 节）+ 把每类控件的处理体抽成自定义块，`forever` 里只留 `如果 (是我的类型) 调用 我的处理`。
- 克隆体上限 300（TurboWarp 可调），**界面元素也算在里面**。一个 40 格的工具栏 + 40 个格子，很快就把预算吃掉。
- 调试时看不出"哪个克隆体在出错"：给每个克隆体一个可见编号（列表监视器或 `说`），比在脑子里数克隆体强。
