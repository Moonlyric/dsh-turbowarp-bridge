# 多小游戏 / 章节式作品：一个「壳」+ N 个关卡

> 适用场景：你要做的是**好几个玩法拼成一个作品**（每章一个小游戏、每关一种机制），
> 而且它们要共用一套菜单、字幕、存档、成就。
>
> 来源：一个 18 角色 / 12181 块的章节式作品 —— 11 个界面（主菜单 + 9 个小游戏 + 结局），
> 共用一套打字机字幕、一套存档码、一套成就表。

---

## 1. 路由：**一个全局字符串变量** + 三态门

所有界面共用一个变量（这里叫 `*T 界面`），值是**字符串**：`0` / `0-2` / `1` / `2A` / `3A` / `4B2` / `E` …
每个小游戏的角色组都挂着**同一个形状的三条门**：

```
当绿旗被点击
  重复执行
    等到 (*T 界面 = 0)          ← 待机门：回主菜单时全体挂起
    …… 自己的初始化 ……
    等到 (*T 界面 = 2A)          ← 进入门：轮到自己了
    …… 主循环 ……
    等到 (*T 界面 = 2Areset)     ← 重玩门：同一个界面，但要从头来
    …… 重置自己的状态再跑一遍 ……
```

- **用字符串不用数字**：`2A` `3B` 一眼知道是第几章第几节；加分支不用重排编号，
  调试时变量监视器里直接看得出在哪一屏。
- **`reset` 后缀是省事的关键**：玩家点「重玩」时不用新建角色、不用新界面值，只把界面设成
  `2Areset`，同一个角色组就会走重置分支。比"销毁重建所有克隆体"稳得多。
- **过场是「当前这关自己把界面设成下一个」**（`2A` 打完里面 `设 *T 界面 = 3A`）。
  简单、没有中央调度表；代价是**加一关要改前一个角色**（见第 5 节）。

## 2. 字幕/对话：全局队列 + 一个「打字机」角色

这是整套壳里最值得抄的部分。**调用方不画字，只往队列里塞两条记录**：

```
全局列表 T 文本信息          ← 一条请求 = 两项：[文本串, 每字等待秒数]

◇ 调用文本显示 string=(文本) timespace=(速度)          ← 只有 2 块，抄到每个角色里
  T 文本信息 += 文本
  T 文本信息 += 速度
```

打字机角色（`问答框`，**397 张造型 = 字形表**）的主循环：

```
当绿旗被点击
  中断 = 0 ; 隐藏
  重复执行
    广播 T 文显清除                       ← 让上一行残留的字克隆体自己删掉
    等待 0 秒
    等到 (长度(T 文本信息) > 0)            ← 没台词就干等，不耗帧
    文本信息i = 0
    计算字符串 (T 文本信息 第1项) 的长度    ← 宽度模型：数字/大写字母 = 10，其余 = 18
    use (长度) divide (速度)              ← 解析出每字的间隔（见下）
    移到 x: (0 − 宽度 ÷ 2)  y: 150         ← **居中靠宽度模型，不靠测量**
    如果 (0 在 分割结果 里) 那么 瞬发       ← 首发标记 = 整行直接出（标题/已读）
    否则
      重复 (文本长度) 次
        文本信息i += 1
        文本克隆()                        ← 换造型成那个字 → x += 10/18 → 建克隆体 → 播字音
        等待 (每字间隔) 秒
    删除 T 文本信息 第1项 ；再删一次        ← 消费掉这条请求（两条记录）
    等到 (中断 = 1)                       ← 行与行之间等玩家点一下
```

要点：

- **一个字一个克隆体**，克隆体的造型就是那个字（所以字库是 397 张造型，不是字体文件）。
  `x += 10` 给窄字符、`x += 18` 给宽字符 —— 等宽近似，但对中文排版够用。
- **居中用"算出来的宽度"**，不用 `碰到边缘` 去试。宽度模型和排字前进量必须**用同一套常量**，
  否则文字会偏。
- **跳过**用三态变量：`0` = 正在打字，`1` = 被要求跳过，`2` = 清场。
  鼠标按下→抬起把它设成 `1`，主循环看到 1 就 `瞬发`（把剩下的字一次性克隆出来，不再逐字等）。
  顺带在这条分支里发成就（"跳过文本"也是成就），只在特定界面下记。
- **队列消费是 `删除第 1 项` ×2**：O(n) 但队列只有 2~4 项，无所谓。队伍长了要改头指针。

## 3. 存档：两级分隔符，读档先清空

```
存档码 = [ 固定串 , 数据区 ]
数据区 = 关^关^关^关 | 成就位串
                  ↑记录间分隔      ↑大区之间分隔
```

```
◇ 加载存档
  重复 (长度(T 所有解锁的关卡)) 次
    存档码 第2项 = 连接(存档码 第2项, 连接(关卡, "^"))
  存档码 第2项 = 连接(存档码 第2项, "|")
  重复 (长度(T 成就)) 次
    存档码 第2项 = 连接(存档码 第2项, 成就 第1项)     ← 单字符字段直接拼，不用分隔符

◇ 读取存档
  删除 T 所有解锁的关卡 全部项 ；删除 T 成就 全部项    ← **先清空**，否则会叠加上次的
  切分 (存档码 第1项) 按 "|"     → 两半
  切分 第一半 按 "^"             → 逐个塞回 关卡列表
  重复 (长度(第二半)) 次 { 成就列表 += (第二半 第 i 个字符) }
```

- **两级分隔**是这类存档的标准做法：记录之间一个符号，大区之间另一个符号，最内层（布尔/成就）
  干脆一字符一位。切分过程复用同一个（传不同分隔符）。
- **读档先 `删除全部项`**：只有一个坑 —— 忘了清空就会把两次存档叠在一起，表现为成就越来越多。
- 存档码存进一个列表（`存档码`），靠"说出来让玩家复制"或扩展写到剪贴板；Scratch 没有文件系统。

## 4. 这层壳的代价（都是可测量的）

| 代价 | 实测 |
|---|---|
| 字幕接口被复制到 **17 个角色** | `调用文本显示` 8 块 ×17 份；同一过程名在 17 个角色里各一份，改签名要改 17 处（分析器会把它列出来） |
| 每章自己硬编码"下一个界面" | 加一关 = 改前一关的角色；没有一张"关卡顺序"表可查 |
| 每帧块数 | 全项目 4292 块/帧；`E 最终结局` 一屏就占 797 块 |
| 广播 25 个、每帧发 | 接收方帽子每帧重建线程 |

**更好的做法**（不改动它也能理解）：把"下一关是谁"放进一张 `关卡顺序` 列表，
过场时 `界面 = 关卡顺序 第 (编号(当前界面)+1) 项`。加关只动表，不动任何角色。

## 5. 最小可抄骨架（三四十块积木）

```
Stage:  全局变量 界面 = "0"；全局列表 台词、存档、成就

「菜单」角色:   重复执行 { 等到 (界面 = "0")  画菜单；点选项 → 界面 = 选项 } 
「字幕」角色:   见第 2 节（队列 + 打字机 + 中断三态）
「第 N 关」角色: 重复执行 {
                  等到 (界面 = 0)
                  初始化
                  等到 (界面 = "N")
                  主循环（结束条件满足 → 界面 = 下一关）
                  等到 (界面 = "Nreset")
                  重置
                }
每个要说话的角色: 抄一份 调用文本显示()（或者让字幕角色读一张台词表，连它都省了）
```

## 6. 在已有作品里加一章的顺序

1. 找一个现有关卡角色，复制它（编辑器里复制角色，或 `scratch_backpack({action:"save", all:true})`
   → `backpack_load({target:"新角色"})`）。
2. 改它的三条门：`0` 不动、`自己的界面值` 换新、`自己的界面值reset` 换新。
3. 改**前一关**里那句"设界面 = 下一关"，指向新界面值（这一步最容易漏）。
4. 菜单那边加一个入口（`界面 = 新值`），并把新值加进存档的"解锁列表"含义里。
5. 跑一遍：`scratch_run({action:"greenflag"})` → 手动点到新关 → `scratch_state` 看 `界面` 变量有没有变。
