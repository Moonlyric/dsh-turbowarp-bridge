# 社区代码惯用法：被十年玩家磨出来的招

> 适用场景：已经懂 Scratch 基本盘，要写游戏/交互逻辑时读。
> 全部来自真实的块组合。**只讲怎么做，不记谁有多少块**——想量规模自己调 `scratch_snapshot` 或 `lab/inspect-sb3.mjs`。

## 1. 缓动数学（easing）——15 块实现指数趋近

一个只有十几块的作品教的最漂亮的招：

```
定义 旋转(方向, 速率)
  左转 (方向) 度
  右转 ((方向) - (方向 × 速率)) 度   // motion_direction 取当前朝向
```

数学本质：`新朝向 = 目标 + (当前-目标)×(1-速率)`——指数衰减趋近目标。同样的结构适用于任何「平滑跟随」：镜头追踪、数值滚动、UI 弹入。Scratch 没有内插函数，`(目标 - 当前) × 0.1 + 当前` 就是全社区的 lerp。

## 2. 列表当数组/结构体

社区作品的标准数据姿势（大项目里几十个列表是常态）：

- `graph.point`：所有节点坐标
- `graph.link`：邻接表（字符串拼的字段，用 `字符 x of` 逐位解析）
- `settings`：配置项
- 命名规则：**同前缀 = 同结构域**。前缀就是命名空间。

访问模式永远是 `第 (index) 项于 [list]`（data_itemoflist）——它就是 Scratch 的 `arr[i]`，引擎类作品里会被调用几百次。

## 3. 数据驱动生成（弹幕的两种流派）

**流派 A：列表驱动**（重型弹幕游戏，29 角色）
弹幕本体不存在角色，全在数据里：列表存每发弹幕的 (类型,x,y,vx,vy,寿命)，一个「物质」精灵每帧算位置渲染。优点：数据量上限高（不受克隆管理开销约束）、可预测、可存档。缺点：渲染要自己写。

**流派 B：克隆体**（东方 style 弹幕，专门一个 `Danmaku` 精灵管克隆池）
```
当接收到 [发射]
  重复 (数量) 次
    生成 [自己] 的克隆体
当作为克隆体启动时
  如果 <类型 = 1> 那么 ... // 克隆体内 if 分支处理变体
  重复执行直到 <出屏 或 命中>
    移动
  删除此克隆体
```
克隆体自管理生命周期，**进门就想好怎么死**。

选型：要美观旋转/独立行为 → 克隆（TW 无上限，但 >500 量级要考虑帧率）；要存档/超大量/复杂数学 → 列表。发回原版 sc 社区的项目克隆数按 300 封顶设计。

## 4. 广播当模块总线

RPG 巨作（Ent/Draw/SFX/UI 四精灵分工）的广播名直接当架构文档读：

`_ Init` → `Start Game` → `Start Main Cycle` → `Game Over` → `Blackout Game Restart`

约定俗成的语法：`_` 前缀 = 内部消息、`__` = 系统级、`Start/End` 配对、动词开头。广播**自带轻量解耦**：发的人不知道谁听，加新监听不用改发送方。

## 5. 单帧主循环（fixed timestep）

引擎派作品的标准骨架：

```
当绿旗被点击
  永远
    广播 [__ Tick]    // 所有系统监听同一拍
    等待 (1/60) 秒
```

需要暂停就加 `如果 <暂停中> 那么等待 (0.01) 秒` 分支。比每个模块自己 forever 更同步。

## 6. 字符串=序列化格式

存档码作品的做法：数字列表转字符串用 `连接`（operator_join）+ 分隔符，读回用 `字符 x of` + `在 ... 中找到 ...`。**序列化独立成一个「模块」**（例如一个专职的 LOADER 精灵），别散在业务里。

## 7. 计时器复位习惯

绿旗点击瞬间 `计时器归零`（sensing_resettimer），后续用 `计时器` 做全局时钟。好处：所有模块共享同一时间轴（各模块用 forever+wait 累加会漂移）。

## 8. 自定义积木 = 函数（但有坑）

- 传引用是**值拷贝**（数字/字符串），要传「引用」就传列表+下标（社区硬通货）
- 自定义积木不重入：递归可以（尾递归 150 层会栈溢），并发调用同一个会排队
- 参数用字符串数字（string_number）最通用，社区作品里绝大多数 reporter 都是它
- **没有返回值**：结果写进变量。两个真实作品独立收敛出的约定是「过程名带编号 + 同名返回槽」：

  ```
  定义 40检测x %s 处的地面h        ← 编号在最前面
      设 out40*地面h = …          ← 返回槽
  调用：40检测x (x) 处的地面h      然后 读 out40*地面h
  ```

  返回槽放**角色局部**变量就够（不会有别人读它），放**全局**变量则意味着"真有多个角色在调"。
- **只在所属角色里可见**：A 调不到 B 的自定义块，这是 Scratch 最容易让人措手不及的一条。
  两条角色都要同一段逻辑，只能复制（代价见 sprite-split.md）或 `广播并等待` 一个库角色
  （参数和返回值都走全局变量，一次调用起一条新线程）。

## 循环必须 warp（否则一帧只走一次）

普通脚本里 `重复 520 次` = 520 帧 ≈ 17 秒。症状是"stepMs 一直 33.3、计数器半天走一格"。
重循环一律塞进**自定义积木**并勾"运行时不刷新屏幕"：

```json
"mutation": { "proccode": "步进 %s", "argumentids": "[\"arg1\"]", "argumentnames": "[\"n\"]",
              "argumentdefaults": "[\"\"]", "warp": "true" }
```

**调用块（`procedures_call`）的 mutation 也要带 `warp: "true"`**，否则只有定义侧生效、调用侧照样刷新。
验证：`scratch_run` 后 200ms 内计数器应该已经走完；没走完就是 warp 没生效。

## 列表做网格时：下标 1-based

```
索引 = (y - 1) * 宽 + x        // 1-based！
第 (索引) 项
```
越界读静默返回 `""`（算成 0），越界写静默不生效。用 `scratch_variable({ action:"get", kind:"list", index })`
核对时它会对越界直接报错，别用整份列表肉眼数。
